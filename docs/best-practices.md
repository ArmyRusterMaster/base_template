# Паттерны Rust (рекомендуемые в проекте)

Рекомендации для продакшн-кода шаблона.

## Newtype

Оборачивайте примитивы в именованные типы, чтобы типобезопасно различать доменные
значения:

```rust
pub struct UserId(uuid::Uuid);
pub struct Email(String);
```

Компилятор не даст перепутать их местами.

## Autoderef

Держите данные владеющими (`String`, `Vec`, `Cow`), а для чтения используйте
`Deref`/`DerefMut` — не плодите ссылочные обёртки. Полезно для методов-флюентов,
совместимых и с `&self`, и со значением.

## Builder

Для объектов со множеством опциональных полей используйте билдер:

```rust
Server::builder()
    .host("0.0.0.0")
    .port(3000)
    .build()?;
```

Например, так устроена загрузка конфигурации: `AppConfig::load()` собирает
значения из слоёв и валидирует результат.

## Typestate

Кодируйте состояния в типах, чтобы некорректные переходы были невозможны на
этапе компиляции:

```rust
struct UnValidated;
struct Validated;
struct Config<S> { ... }
```

Именно такой подход использован в `src/config.rs`: только валидированный
конфиг (`validate()`) возвращает `SocketAddr`, а невалидные значения не
«продаются» дальше.

## Общие типы — в крейте воркспейса

Если тип нужен и SSR-серверу, и WASM-клиенту, он живёт в `crates/core-shared`
(пример: `HealthResponse`, `ConnectorHealthDto`) — и только там:

```rust
use core_shared::HealthResponse; // и в src/app.rs (клиент), и в src/main.rs (сервер)
```

Правила:

- крейт не зависит от `leptos`, `axum`, `tokio` — иначе он не соберётся под
  `wasm32-unknown-unknown`;
- DTO не дублируются «локально» в `src/` и не тянут внутренние модели БД/домена;
- контракт (имена и порядок полей) фиксируется тестом на JSON, чтобы изменения
  не ломали клиента молча;
- серверные детали (коннекторы, конфиг, ошибки, логи) в общий крейт не
  переезжают — для них есть `src/connectors`, `src/config`, `src/error`,
  `src/logging`.
